# Connect to an external CPA

**External CPA** uses ECPA's desktop management pages with an already-running CLIProxyAPI v8 instance. The instance can run on this computer, on a private network, or on a server you administer.

1. Open the **Built-in CPA** target selector below the sidebar brand, then choose **Add external CPA**. In Easy Mode, exit to the regular workspace first. Keep the built-in core running while verifying the connection. A failed verification leaves it alone.
2. Enter the server’s base URL (for example `http://127.0.0.1:8317` or `https://cpa.example.net/team/cpa`) and its **plaintext management key**. Do not use a client API key, hashed management key, `/v1`, or `/v8/management`. A reverse-proxy prefix is supported; URL credentials, query parameters and fragments are not. Non-loopback clients may require `management.allow-remote` and access through the server’s firewall or reverse proxy. Limit access to the people and networks that need it.
3. Choose **Verify and connect**. After verification ECPA stops only its managed local core and changes the target in the existing sidebar, without reopening the window.
4. Keep using the original desktop pages. **OAuth**, **API Access**, routing and quota use the selected management API; **Quick Configuration** edits the selected server’s configuration, not the built-in YAML. Under **Agent Configuration**, choose a client key and model to write the remote service URL (including any proxy prefix) into the agent configuration on this computer. The management key is never used as an agent credential. Changes apply to the server shown in the target selector. Client keys are masked by default; deleting keys can disconnect existing clients.
5. Add more instances from the same menu, or select a saved URL and verify it without re-entering its key. Returning to Built-in CPA starts its managed kernel, keeps saved instances, and does not stop their servers. If ECPA was originally opened on an external instance, it restarts the desktop app to initialize the built-in environment. This explicit switch starts the kernel even when automatic startup is off. To remove a saved URL and its key, switch away from it, select it in the menu, and choose **Forget instance**.

Both HTTP and HTTPS endpoints are supported, including public hostnames and IP addresses. For HTTPS, certificate checks remain enabled. ECPA does not use a client-side system proxy or follow redirects. Enter the final endpoint if a proxy redirects you.

ECPA sends the management key only in the `Authorization` header. The connection is saved separately from Built-in CPA in `remote-cpa.json` (owner-only on Unix; Windows inherits the directory’s permissions). Keep that settings directory private. A saved key is reusable only at the same normalized URL.

Only the selected instance is collected. Built-in history stays in `usage-records/usage.db`. External instances have separate SQLite databases under `usage-records/instances/`, keyed by normalized base URL (including the proxy prefix), not by credential. Rotating a management key therefore retains history. Home, live routing, usage reports, custom pricing and database maintenance use the selected database. Local Agent usage is a separate desktop data source.

External collection consumes the v8 HTTP usage queue. Enable usage statistics on the instance; requests produced while unselected can only be recovered while the server still retains them. Another queue consumer may remove records first. A disconnect does not remove already collected history. Removing a saved connection does not erase its database.

Advanced settings use conditional field writes or atomic batch patches. Document writes are reserved for changes the field API cannot represent or explicitly rejects as unsupported. A conflict, authentication failure or interrupted write is not retried through YAML. TLS certificates and log directories are on the CPA host, not necessarily on this computer.

Model aliases are read and edited on the selected CPA. In Logs & diagnostics, enable and save file logging before viewing the latest 200 lines from that server. External access (the desktop reverse proxy) is built-in only: the external instance does not start or poll a proxy on this computer. Enter certificate and OAuth directory paths as they exist on the CPA host; restart that service on its host if required.

The server must support the CPA v8 management API and configuration ETags for conditional client-key updates. Connection failures do not fall back to Built-in CPA. A desktop-only capability such as opening a server directory, reading the built-in usage database or replacing the server executable is not a remote management API. ECPA does not execute these operations on the local CPA as a fallback.
