# Connect to an external CPA

**Remote CPA** manages client API keys on an already-running CLIProxyAPI v8 instance. The instance can run outside the ECPA folder on the same computer, on a private network, or on a server you administer. ECPA never takes over the external process.

1. Open the **Built-in CPA** target selector below the sidebar brand, then choose **Connect Remote CPA**. In Easy Mode, exit to the regular workspace first. If ECPA is running its own Built-in CPA, stop that core through Home’s runtime controls before switching. This does not stop your external CPA.
2. Enter the server’s base URL (for example `http://127.0.0.1:8317` or `https://cpa.example.net/team/cpa`) and its **plaintext management key**. Do not use a client API key, hashed management key, `/v1`, or `/v8/management`. A reverse-proxy prefix is supported; URL credentials, query parameters and fragments are not. Non-loopback clients may require `management.allow-remote` and access through the server’s firewall or reverse proxy. Limit access to the people and networks that need it.
3. Choose **Verify and connect**. After verification, fully quit and reopen ECPA: the Remote connection is saved but not yet active. Choose **Cancel switch and keep Built-in CPA** if you change your mind before reopening.
4. The Remote workspace shows the selected server and automatically loads its client keys. Keys are masked until you **Reveal keys** or **Edit keys**. A save replaces that server’s list and must leave at least one key. Removing keys requires confirmation and can disconnect clients. If a save fails or is unconfirmed, ECPA keeps your draft in memory. Reload the latest server keys, compare them with your draft, then confirm that you reviewed them before saving again.
5. In the Remote header’s target selector, **Change server** verifies a new endpoint before switching immediately. It does not send the old server’s management key to the new one. **Return to Built-in CPA** clears the saved Remote management key, leaves the external CPA running, and restores the built-in workspace after a full quit and reopen. Save or deliberately discard unsaved key edits before leaving their server.

Public endpoints require HTTPS with a trusted, valid certificate. Plain HTTP exposes the management key and response to observers. Use it only on localhost or on a trusted private network with a literal RFC 1918 IPv4 or IPv6 unique-local address. ECPA does not bypass certificate checks, use a client-side system proxy, or follow redirects. Enter the final endpoint if a proxy redirects you.

ECPA sends the management key only in the `Authorization` header. The connection is saved separately from Built-in CPA in `remote-cpa.json` (owner-only on Unix; Windows inherits the directory’s permissions). Keep that settings directory private. A saved key is reusable only at the same normalized URL.

Remote uses `/v8/management/config/config-version` and `/v8/management/config/access/api-keys`. The server must support configuration ETags: conditional writes avoid overwriting concurrent edits. Connection failures never fall back to Built-in CPA. OAuth, provider credentials, usage, agent integrations, plugins, version updates and process controls remain available only in built-in mode in ECPA.
