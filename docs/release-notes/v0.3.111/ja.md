## 追加

- **同梱の Codex モデルカタログに `gpt-oss-120b-medium` を追加**: このモデルはアプリに同梱されるカタログ（revision 9）に含まれ、追加のダウンロードなしで Codex のモデル選択に表示されます。

## 改善

- **ACP のモデル名をそのまま公開**: 従来は ACP プロバイダーが改名済みのモデルにさらに別名を付けていましたが、Claude Desktop の別名テーブルでは「改名の改名」を表現できません。`acp/` プレフィックス付きのモデル名をそのまま公開し、別名フィールドを廃止しました。
- **Claude Desktop が管理設定を「要注意」と表示しなくなります**: `behavesAs` を管理対象のモデル項目に書き込まなくなりました。この項目を認識しない Desktop のビルドは設定全体を異常と判定するためです。Desktop が既に認識している系統ルート（`claude-opus-5`、`claude-sonnet-5`、`claude-haiku-4-5`）を直接公開し、上流のモデル名は `labelOverride` に残します。旧バージョンが書いた値が復活することもありません。
- **ACP API のストリーミングを修正**: Chat Completions と Responses のクライアントは、完全な OpenAI 互換ストリームを受け取れるようになりました。最初の assistant ロール差分、テキストまたはインデックス付きツール呼び出し、単一の終了理由と `[DONE]` を含み、各チャンクは同じ completion ID、モデル、作成時刻を共有します。出力キューは輻輳時にバックプレッシャーをかけつつキャンセル可能なまま動作し、チャンクを取りこぼしません。CLI がトークン数を返さない場合、使用量を捏造しません。

## 修正

- **Antigravity の使用量が重複計上され、かつ失われていました**: 使用量スキャナーは同一セッションのすべてのミラー（`transcript.jsonl`、`transcript_full.jsonl`、`chunks/**`、IDE とバックアップのコピー）を計上していたため、合計が実際の数倍になり、一部のリクエストのモデルが「unknown model」と表示されていました。各セッションは単一の正規 transcript から一度だけ計上され、モデルはリクエストのステップごとにセッション DB から読み取り、設定ラベルをフォールバックとして使います。同一サンプルは重複排除しつつ、リトライと圧縮チェックポイントは保持します。アップグレード後の初回同期で Antigravity の行が一度だけ再構築され、合計は実際の値に戻ります。
- **ファイルが読めないと Antigravity の使用量が消えることがありました**: セッション内の他のファイルが一つでも読めると、読めなかったファイルのキャッシュ行まで削除されていました。読み取りに失敗した場合はキャッシュ行を保持し、ミラーの transcript はファイル名ではなく実際に網羅するリクエストで比較し、旧キーは置き換え後のキーと併存させず移行するようにしました。
- **ACP API の書き込み失敗で原因が失われていました**: Claude Desktop の別名マッピング保存が `invalid_config` で失敗していました。ACP プロバイダーが `proxy-url` をプロバイダーレベルに書いていたためで、コアは `openai-compatibility` エントリでこの書き方を拒否します。キーエントリ内に書くよう変更し、既存のプロバイダーレベルの値をキーエントリへ正規化し、書き込み失敗のメッセージにコアの元のエラーを付け加えました。
- **ACP API が補完の途中で失敗しても成功に見えることがありました**: 最初のチャンク以降の上流障害が切り詰められた成功として報告されていました。出力前の障害は HTTP エラーを返し、出力後の障害は成功の終了理由も `[DONE]` も伴わない終端 SSE エラーを送出します。失敗したターンが完了済みに見えることはありません。
