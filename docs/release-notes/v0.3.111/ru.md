## Добавлено

- **`gpt-oss-120b-medium` во встроенном каталоге моделей Codex**: модель включена в поставляемый каталог (revision 9) и доступна в выборе модели Codex без отдельной загрузки.

## Улучшено

- **Модели ACP публикуются под исходными именами**: провайдер ACP добавлял псевдоним поверх уже переименованной модели, а таблица псевдонимов Claude Desktop не умеет выражать «переименование переименования». Теперь модель публикуется под именем с префиксом `acp/` без поля псевдонима.
- **Claude Desktop больше не помечает управляемую конфигурацию как требующую внимания**: поле `behavesAs` больше не записывается в управляемые записи моделей, поскольку сборки Desktop, не знающие это поле, считают всю конфигурацию некорректной. Публикуются известные Desktop семейные маршруты (`claude-opus-5`, `claude-sonnet-5`, `claude-haiku-4-5`), а исходное имя модели остаётся в `labelOverride`. Значение, записанное старой версией, больше не восстанавливается.
- **Исправлена потоковая передача ACP API**: клиенты Chat Completions и Responses теперь получают полный поток, совместимый с OpenAI: начальная дельта роли assistant, текст или индексированные вызовы инструментов, единственная причина завершения и `[DONE]`, при этом все фрагменты используют один completion ID, модель и время создания. Очереди вывода применяют обратное давление, оставаясь отменяемыми, и больше не теряют фрагменты при нагрузке. Если CLI не сообщает количество токенов, использование не выдумывается.

## Исправлено

- **Использование Antigravity завышалось и терялось**: сканер учитывал каждую копию сессии (`transcript.jsonl`, `transcript_full.jsonl`, `chunks/**`, копии IDE и резервные копии), поэтому итог в несколько раз превышал реальный, а модель части запросов отображалась как «unknown model». Теперь каждая сессия учитывается один раз из одного канонического transcript, модели читаются по шагу запроса из базы данных сессии с меткой настроек как резервным вариантом, а идентичные образцы дедуплицируются с сохранением повторов и контрольных точек. Первая синхронизация после обновления один раз перестраивает данные Antigravity, и итог возвращается к реальному значению.
- **Использование Antigravity могло исчезнуть после ошибки чтения файла**: если транскрипт сессии не читался, её кэшированные строки всё равно удалялись, потому что любой другой читаемый файл сессии разрешал очистку. Теперь кэш сохраняется при любой ошибке чтения, зеркальные транскрипты сравниваются по реально покрытым запросам, а не по имени файла, а старые ключи переносятся, а не подсчитываются вместе с заменами.
- **Ошибка записи ACP API теряла первопричину**: сохранение сопоставления псевдонимов Claude Desktop завершалось с `invalid_config`, поскольку провайдер ACP записывал `proxy-url` на уровне провайдера, что ядро не принимает для записей `openai-compatibility`. Теперь поле записывается внутри записи ключа, существующее значение на уровне провайдера нормализуется в записи ключей, а исходный текст ошибки ядра добавляется к сообщению о сбое записи.
- **ACP API мог завершиться ошибкой в середине ответа, выглядя успешным**: сбой вышестоящего сервиса после первого фрагмента сообщался как усечённый успех. Теперь сбои до вывода возвращают HTTP-ошибку, а сбои после вывода порождают терминальную ошибку SSE без успешной причины завершения и `[DONE]`, поэтому неудачный ход больше не выглядит завершённым.
