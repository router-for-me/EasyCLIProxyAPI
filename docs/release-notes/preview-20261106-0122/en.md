The reverse proxy for external HTTPS access actually works in this build. Requests from another machine on your network now terminate TLS at the desktop app and are forwarded to the local CPA kernel, including streaming responses. Certificate paths survive app restarts, saving a bad configuration no longer stops a proxy that was working, and the status page tells you the real address other devices should use instead of a generic wildcard.

If you hit problems, tell us on [Discord](https://discord.gg/your-discord-invite) or open an issue on [GitHub](https://github.com/router-for-me/EasyCLIProxyAPI/issues).

## Fixed

- **External HTTPS access never actually answered clients**: enabling the reverse proxy did not bind a listener, so connections to the advertised port refused even though the page said it was running. The proxy now binds the configured host and port, accepts TLS connections, forwards requests to the kernel over HTTP or HTTPS depending on the kernel's own TLS setting, and reports bind or certificate failures back to the page instead of leaving the toggle in a half-started state.
- **Saving a bad configuration killed a working proxy**: an invalid certificate path, a missing private key, an occupied port, or a failed write could stop the healthy listener and overwrite the saved good settings. Invalid or unsuccessful saves now leave the previous running configuration and saved file untouched, and Discard restores them.
- **Restarting the app forgot the certificate paths**: the PEM certificate and private key fields only lived in memory. They are now persisted and restored on startup so an enabled proxy comes back up with the same settings.
- **Proxy status claimed the wrong lifecycle**: the running flag reflected whether a start request was submitted, not whether the listener was actually bound. The page now reads the real state, shows the actual listening address and target, and a failed start leaves a readable error instead of a false Running state.
- **Stopping could fail for irrelevant reasons**: turning the proxy off was blocked by invalid draft values in unrelated port fields, and a failed config write could prevent the listener from actually shutting down. Disable now always releases the listener; saving a disabled draft keeps valid edits so you can stage settings before enabling, while an invalid draft still reports an error when the proxy is already stopped.
- **Startup probe used the wrong address after hardening**: when the proxy was enabled, the kernel was correctly restricted to loopback but the startup readiness check still probed the original LAN or IPv6 host, killing a healthy kernel after a timeout. The check now uses the effective generated configuration.
- **Delayed restarts could revive a stopped proxy**: a kernel start that waited on a shared lock could return a stale running=true status and bring the listener back after the kernel had been stopped. The restore path now checks the real process state before and after applying the saved config.
- **Temporary accept errors shut the listener down permanently**: a transient error such as file-descriptor exhaustion or an aborted connection exited the accept loop. These errors now retry with a bounded 50–200 ms backoff and only give up after ten consecutive failures.
- **Custom target port was silently ignored**: an explicit target port was overwritten by the kernel port at save and again at startup. A nonzero target is now preserved; target port 0 follows the kernel port, which remains the default.

## Improved

- **The access route is clearer about what to give clients**: the wildcard bind address is labelled a draft preview, the running page shows the actual server LAN address and port to hand to clients, and the enable hint says the switch only takes effect after saving.
- **PEM path inputs no longer trigger browser autofill**: certificate and key fields opt out of the WebView autofill popup that was causing crashes on Windows, and invalid file selections surface as inline field errors instead of unhandled exceptions.
- **The reverse proxy is exercised end-to-end in tests**: the suite now covers plain and TLS kernel targets, native kernel TLS forwarding, kernel port changes, app restarts, manual kernel starts, streaming and non-streaming requests through a real kernel, and shutdown across normal and corrupt-config paths.
