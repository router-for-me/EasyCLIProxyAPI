## 追加

- **ACP のツール呼び出し往復**：関数ツールは組み込みの認証付き MCP アダプター経由で公式 CLI に渡されるようになり、Chat Completions と Responses のクライアントは `tool_calls` を受け取り、実行して同じ実行に結果を返せます。ストリーミングにも対応し、待機中の呼び出しは CLI プロセスを保持したまま 10 分で失効します。完了済みの呼び出し ID が二重に配信されることはありません。ユーザー側で MCP を用意する必要はありません。

## 改善

- **ACP クライアント互換性**：空または null の `tools`、ツールなしの `tool_choice` auto、明示的な `tool_choice: none` を受け付けます。一般的なクライアント項目 `n: 1`、`store: false`、`response_format` の text、`parallel_tool_calls`、`user`、`metadata`、`prompt_cache_key`、`safety_identifier` は検証のうえ受け付けます。`max_tokens`、`max_completion_tokens`、`temperature`、`top_p` は互換のため受け付け、CLI が適用できない非 null 値はリクエストを拒否せずレスポンスヘッダー `x-ecpa-ignored-parameters` に列挙します。
- **ACP のシステム指示の伝達**：system と developer の指示は、CLI が宣言するシステムプロンプト追記機能または公式 Antigravity 拡張を通じて個別に渡すようになり、Agent 自身の既定プロンプトを保持します。どちらの機能もない CLI では、指示がある場合に明確な更新要求エラーを返します。
- **ACP API の開始と停止**：API カードは明確な開始／停止スイッチになり、停止済み、開始中、開始済みで接続待ち、開始済みの状態を区別します。アクセスが有効な間は、アカウントが未接続でもモデルが空でも停止はいつでも可能です。開始にはアカウント接続が必要で、不足している前提はカード内に明示します。エラーはカード内に表示され、スイッチは操作可能な状態に戻ります。

## 修正

- **ACP API アクセスを確実に無効化できなかった問題**：アクセスは既定で無効になり、ログイン、更新、アカウント切り替え、アプリ再起動で有効になったように見えることはなくなりました。無効化は無効の意図をアトミックに保存し、待機中のツールセッションとリスナーを破棄し、旧形式と v8 の両方の設定レイアウトから管理対象 provider を削除します。何度実行しても安全で、失敗時は無効側に倒れるため、クリーンアップのエラーで残留アクセスが次回起動時に復活することはありません。
