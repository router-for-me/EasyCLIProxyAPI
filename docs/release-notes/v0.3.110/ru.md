## Добавлено

- **Циклы вызова инструментов в ACP**: функции-инструменты теперь передаются официальному CLI через встроенный MCP-адаптер с аутентификацией, поэтому клиенты Chat Completions и Responses могут получать `tool_calls`, выполнять их и возвращать результаты в то же выполнение. Поддерживается потоковая передача; ожидающие вызовы сохраняют процесс CLI и истекают через десять минут, а завершённый идентификатор вызова не может быть доставлен дважды. Устанавливать MCP на стороне пользователя не требуется.

## Улучшено

- **Совместимость с клиентами ACP**: пустой или null `tools`, `tool_choice` auto без инструментов и явный `tool_choice: none` теперь принимаются. Распространённые поля клиентов — `n: 1`, `store: false`, `response_format` типа text, `parallel_tool_calls`, `user`, `metadata`, `prompt_cache_key` и `safety_identifier` — проверяются и принимаются. `max_tokens`, `max_completion_tokens`, `temperature` и `top_p` принимаются для совместимости, а значения, которые CLI не может применить, перечисляются в заголовке ответа `x-ecpa-ignored-parameters` вместо отклонения запроса.
- **Передача системных инструкций ACP**: инструкции system и developer теперь передаются отдельно через заявленную CLI возможность добавления системного запроса или официальное расширение Antigravity, сохраняя собственные инструкции агента по умолчанию. CLI без обеих возможностей возвращает явную ошибку о необходимости обновления, если инструкции присутствуют.
- **Запуск и остановка ACP API**: карточка API теперь использует явный переключатель запуска и остановки с отдельными состояниями: остановлено, запуск, запущено с ожиданием подключения и запущено. Остановка доступна всегда, пока доступ включён, даже при отключённой учётной записи или без моделей; для запуска требуется подключённая учётная запись, а отсутствующее условие поясняется прямо в карточке. Ошибки показываются в карточке, и переключатель возвращается в рабочее состояние.

## Исправлено

- **Доступ по ACP API не отключался надёжно**: теперь доступ по умолчанию выключен, и вход, обновление, переключение учётных записей или перезапуск приложения больше не выглядят как его автоматическое включение. Отключение атомарно сохраняет намерение «выключено», очищает ожидающие сеансы инструментов и слушатель, а также удаляет управляемый провайдер из обеих схем конфигурации — старой и v8. Операция идемпотентна и при ошибке переходит в выключенное состояние, поэтому сбой очистки не оставит остаточный доступ, который включится при следующем запуске.
