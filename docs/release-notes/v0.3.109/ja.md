## 追加

- **ACP アクセス（Antigravity）**：OAuth ページに「ACP アクセス」タブを追加しました。Google の公式認証で Antigravity CLI にログインでき、複数のアカウントを保存して切り替えられます。CLI は全アカウントで共通、ログイン状態は個別に保存されます。接続後はテストメッセージでモデルを検証でき、API を有効にするとアカウントのモデルが `acp/<モデルID>` として予約済みの OpenAI 互換 provider に登録され、既存の CPA アドレスとキーで呼び出せます。CLI の検出とインストール、現在のアカウント情報、接続の詳細もこのタブにまとめています。
- **ACP の思考レベル**：リクエストの `reasoning_effort`、`reasoning.effort`、`thinking.effort` は、公式モデルの該当するレベル変種に解決されます。レベルは公式モデル ID の接尾辞から判定します。レベル未宣言、存在しないレベル、値の衝突は明示的なエラーになり、黙って無視されることはありません。ACP provider は思考レベルの宣言を自動で書き込まず、レベルは従来どおり手動設定です。
- **ACP のマルチターン**：ブリッジは `system`、`user`、`assistant` メッセージを受け付け、履歴を `System:` / `User:` / `Assistant:` として 1 つのプロンプトにまとめます（公式 CLI はリクエストごとに独立したセッションを使うため）。最後のメッセージはユーザーである必要があります。単一のユーザーメッセージは従来どおりそのまま渡されます。

## 改善

- **ACP カードのレイアウト**：アクセスページの 2 つのカードを同じ高さにそろえ、未接続時はアイコンと説明による簡潔なロック状態にしました。枠の中に枠がある破線表示は廃止しています。接続済みまたは API 有効時は見出しアイコンが成功色になり、ホバー時に軽い影が出ます。狭い幅ではボタンが折り返します。

## 修正

- **ヘルスチェックのプローブ予算**：プローブ要求の予算を引き上げ、「生成枠を使い切った」ことを独立した理由として報告するようにしました。他の失敗と混同されません。
- **Gemini Interactions の新しいイベント名**：ヘルスチェックは従来 `content.delta` / `interaction.complete` しか認識せず、テキストも `interaction.outputs` からのみ読んでいたため、`step.delta` / `interaction.completed` / `steps` を使う正当なストリームが初回トークン欠落と誤判定されていました。現在は新旧両方のイベント名に対応し、完了テキストは `steps` または `outputs` から読み取り、ステータス欠落は成功として扱い、失敗とキャンセルは明示的に拒否します。
- **モデル別名の同期で複数語のキー**：別名とエージェントの YAML 更新は `yaml_serde_edit` を経由しており、その依存パーサーは引用符のない複数語キーでマッピングを切り捨てるため、ワンクリック接続時の正当な編集が互換性チェック失敗と判定されていました。関連するすべての経路を `serde_norway` の解析と `yaml-edit` のレンダリングに切り替え、複数語キーの別名同期が正常に戻りました。
