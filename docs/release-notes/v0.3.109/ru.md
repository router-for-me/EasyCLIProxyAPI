## Добавлено

- **Доступ по ACP (Antigravity)**: на странице OAuth появилась вкладка ACP Access. Вход в Antigravity CLI выполняется через официальную авторизацию Google, можно сохранять несколько учётных записей и переключаться между ними — CLI общий для всех, а состояние входа хранится отдельно. После подключения можно отправить одно тестовое сообщение для проверки модели; при включении доступа к API модели учётной записи регистрируются как `acp/<model-id>` в зарезервированном OpenAI-совместимом провайдере и вызываются по существующему адресу и ключу CPA. Вкладка также содержит обнаружение и установку CLI, сведения о текущей учётной записи и подробности подключения.
- **Уровни рассуждений для ACP**: `reasoning_effort`, `reasoning.effort` и `thinking.effort` преобразуются в соответствующий вариант уровня официальной модели; уровни определяются по суффиксу идентификатора модели. Если уровни не объявлены, уровень неизвестен или значения противоречат друг другу, возвращается явная ошибка, а не молчаливое игнорирование. Провайдер ACP не записывает объявления уровней автоматически — уровни по-прежнему настраиваются вручную обычным способом CPA.
- **Многоходовой чат для ACP**: мост принимает сообщения `system`, `user` и `assistant` и объединяет историю в один запрос блоками `System:` / `User:` / `Assistant:`, поскольку каждый запрос использует отдельную сессию официального CLI. Последнее сообщение должно быть от пользователя. Одиночное сообщение пользователя передаётся без изменений.

## Улучшено

- **Макет карточек ACP**: две карточки на странице доступа теперь одинаковой высоты, а состояние без подключения оформлено как компактная блокировка со значком и пояснением — без пунктирной рамки внутри рамки. При подключении или включённом API значок заголовка становится успешным цветом, карточка слегка приподнимается при наведении, а на узкой ширине кнопки переносятся.

## Исправлено

- **Бюджет проверки работоспособности**: бюджет запроса проверки увеличен, а исчерпанный бюджет генерации сообщается как отдельная причина, а не смешивается с другими сбоями.
- **Новые имена событий Gemini Interactions**: проверка работоспособности распознавала только старые события `content.delta` / `interaction.complete` и читала текст только из `interaction.outputs`, поэтому корректный поток с `step.delta` / `interaction.completed` / `steps` считался потоком без первого токена. Теперь поддерживаются оба поколения событий, текст завершения читается из `steps` или `outputs`, отсутствующий статус считается успехом, а состояния failed и cancelled отклоняются явно.
- **Синхронизация псевдонимов с многословными ключами**: обновление YAML псевдонимов и агентов шло через `yaml_serde_edit`, чей транзитивный парсер обрезал отображения на многословных ключах без кавычек, из-за чего законные изменения при подключении в один клик считались провалом проверки совместимости. Теперь все связанные пути используют разбор `serde_norway` и рендеринг `yaml-edit`, и синхронизация многословных ключей снова работает.
