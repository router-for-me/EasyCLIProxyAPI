## Добавлено

- **Автоматические обновления в управлении версиями**: приложение и ядро могут обновляться без ручной загрузки. Выберите, за чем следить, и новые версии будут незаметно загружаться во время работы и устанавливаться при следующем запуске, до старта локальных служб. По умолчанию функция выключена, а ручное и автоматическое обновление никогда не выполняются одновременно. Смена источника загрузки, канала или прокси отменяет сохранённую загрузку, а версия, установка которой не удалась, блокируется до сброса ошибки вместо бесконечных повторов. Подробнее в [описании автоматических обновлений](docs/automatic-updates.md).

## Улучшено

- **Страница управления версиями стала плотнее**: она использует доступную ширину и уменьшенные отступы, поэтому настройки обновления и обе карточки версий помещаются без высоких пустых строк, вытеснявших кнопки за пределы экрана.

## Исправлено

- **Неверный расчёт расхода у плагинных исполнителей**: записи плагинных исполнителей использовали соглашение о токенах OpenAI, тогда как сами исполнители следуют соглашению вышестоящего протокола. Запрос Claude только с записью в кэш показывал 100 % попаданий, не учитывал некэшированный ввод и дважды списывал запись в кэш, а токены рассуждений Gemini терялись и не оплачивались. Теперь читается независимый от протокола `token_breakdown`, который ядро уже предоставляет.
- **Сохранение псевдонимов не работало при наличии хвоста в конфигурации**: YAML-редактор не принимает документ с неотносимыми токенами после него, поэтому конфигурация, собственный парсер которой останавливается в конце документа, не могла сохранить псевдонимы — каждый раз возникала ошибка «Content after the document could not be parsed». Теперь хвост отделяется, редактируется отдельно и возвращается обратно байт в байт.
- **Обновление ядра не удавалось, если двоичный файл был только для чтения**: копирование переносило биты прав источника, поэтому перезапись ядра с правами `0555` создавала временный файл только для чтения и следующая запись падала с `EACCES`. Теперь в Unix временный файл синхронизируется через дескриптор только для чтения, в Windows сохраняется дескриптор для записи, а бит записи владельца восстанавливается, чтобы последующие обновления могли заменить файл.
- **Незавершённая настройка автообновления молча отключала функцию**: конфигурация с включённым обновлением, но без выбранной цели целиком заменялась значениями по умолчанию при очистке, а очищенная конфигурация записывалась обратно, из-за чего сброс становился постоянным. Теперь сокращается только недостижимая часть, остальная запись сохраняется, а повторная загрузка ничего не пишет, если запись уже согласована.
- **Замена слова `codex` использовала неверный регистр**.
