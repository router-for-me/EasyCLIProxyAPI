## 新增

- **版本管理支持自动更新**：应用與核心都可以自行更新，无需手动下載。可选择要跟随的更新对象，应用运行期间静默下載新版本，并在下次啟動时、本地服务啟動之前安装。該功能預設关闭，手动更新與自动更新不會同时進行。更改下載源、通道或代理會使已下載的更新失效；安装失敗的版本會保持阻塞状态，直到清除失敗紀錄，而不會無限重試。详见[自动更新说明](docs/automatic-updates.md)。

## 改進

- **版本管理頁面更紧凑**：頁面會充分利用可用寬度并收紧間距，更新設定與两张版本卡片不再因高大的空行把操作按鈕挤到首屏之外。

## 修复

- **插件执行器的用量计算错误**：插件执行器的紀錄回退到了 OpenAI 的 token 约定，而這类执行器遵循的是上游協定的约定。僅寫入快取的 Claude 請求會报告 100% 快取命中率、把未快取输入按零計費并重複收取快取寫入費用，Gemini 的思考 token 则被从輸出中丟棄且未計費。现在改為讀取核心已提供的、與協定无关的 `token_breakdown`。
- **配置檔案带有尾部内容时別名保存失敗**：YAML 编辑器无法接受文档之後无法归属的剩余标记，因此对于自身讀取器在文档结尾即停止的配置檔案，每次保存別名都會以「Content after the document could not be parsed」失敗。现在會把尾部内容单独拆出、分别编辑，再逐字节原样追加回去。
- **核心二進制為只读时更新失敗**：複製操作會沿用源檔案的權限位，因此覆盖一個 `0555` 權限的核心會得到一個只读暫存檔案，後續寫入以 `EACCES` 失敗。现在在 Unix 上透過只读控制代碼同步暫存檔案，在 Windows 上保留可写控制代碼，并還原属主写權限，使後續更新仍可覆盖。
- **未完成的自动更新設定會静默关闭該功能**：配置中启用了自动更新但未选择任何更新对象时，清理阶段會把整段設定替换為預設值，而清理後的配置又會被写回，导致這次重置永久生效。现在只收敛其中不可达的部分，保留紀錄的其余内容；當紀錄本身已经一致时，重新加载不會寫入任何内容。
- **`codex` 词语替换的大小写有误**。
