## 新增

- Linux 新增系統匣：可從系統匣開啟主介面、查看核心狀態、啟動或停止核心、重新啟動核心及退出應用程式；支援關閉視窗後留在系統匣及靜默啟動。

## 優化

- 內建核心更新至 8.0.3。應用程式已適配核心 v8 的設定結構與管理介面，包括 API 提供者、存取金鑰、OAuth 模型別名、請求設定等資料的讀取與儲存。
- 改進窄視窗下的頁面配置；為語言選單、頁面分頁、對話框和使用紀錄表格補上鍵盤操作、焦點管理與輔助使用標示。使用紀錄的欄寬也可透過鍵盤調整。
- 未匹配到支援的語言時預設使用英文；將原先寫死為中文的後端提示統一為英文，系統匣選單則跟隨應用程式語言顯示。

## 修復

- 修復 macOS 替換應用程式套件後，可能找不到舊套件內 OAuth 憑據目錄的問題；從更新備份將憑據及其日誌復原至持久化目錄。自動更新後若設定載入失敗，會觸發回復，避免以預設設定確認升級成功。
- 修復核心升級時新版範本預設值可能覆蓋原有設定的問題。從 v7 升級至 v8，以及更新部分已遷移的 v8 設定時，保留現有設定，避免 OAuth 憑據目錄、連接埠及存取金鑰等項目被重設。
- 修復未標記版本的 v8 設定在啟動或修改存取金鑰時，可能誤將上游 API 憑據覆蓋為存取金鑰的問題。
- 核心啟動日誌改為附加寫入，啟動或重新啟動核心時保留歷史啟動輸出。
- 修復核心 v8 設定缺少可選節點時頁面讀取失敗的問題；改善首次建立模型別名及儲存失敗後的回復，避免將空的設定父節點誤判為其他修改。
- 修復 Claude Code 透過 CPA 閘道執行時可能觸發伺服器端自動模式檢查的問題。
- 修復 macOS 升級後舊版相對路徑 OAuth 憑據目錄可能導致既有憑據無法辨識的問題。當相對路徑目錄中沒有憑據，而持久化目錄中有憑據時，會自動恢復使用原有憑據。
- Linux 無可用系統匣時保留主視窗，避免靜默啟動或最小化後無法重新開啟應用程式。
- 將舊版相對路徑 OAuth 憑據目錄的自動復原擴展至 Windows 和 Linux，並改善 macOS 的路徑判斷；復原失敗時保留現有設定與憑據。
- 修正各平台 OAuth 憑據目錄與核心日誌目錄的路徑解析，使開啟目錄和寫入啟動日誌的位置與核心實際使用的路徑一致。
- 修復未標記版本但使用 v8 結構的核心設定，在儲存 TLS、日誌及 OAuth 憑據目錄等項目時可能寫入錯誤位置的問題；同時支援更新行內 YAML 對應表。
