本次更新修好了两件直接影响升级与下载的事：客户端切换更新通道后，现在能正确识别出有新的构建并给出「立即升级」；手动下载按钮也不再绕过你选的下载源，会按当前选择的镜像（GitHub 官方 / gh-proxy / ghfast / 自定义）拼出下载链接，国内直连打不开 GitHub 的人也能正常下到包。

如果你在使用中遇到问题，请通过 [QQ群](https://qm.qq.com/q/3queDaIG) 或 [GitHub Issues](https://github.com/router-for-me/EasyCLIProxyAPI/issues) 反馈，我们会尽快处理。

## 修复

- **切换更新通道后没有「立即升级」**：带时间戳的构建版本号形如 `0.3.6-preview.20261106-1137`，按语义化版本规则永远低于 `0.3.6`，所以从正式版切到其他更新通道时，更新检查判定"没有新版本"，只剩一个下载按钮。现在这类构建会被正确识别为新版本，切换通道后即可直接应用内升级。
- **手动下载忽略了所选下载源**：桌面客户端的下载按钮直接用清单里的 GitHub 原始地址打开浏览器，选中的镜像源只用于拉取版本清单，真正下载包时没有生效。现在下载链接会按当前下载源套用镜像前缀，选 `ghfast.top` 或 `gh-proxy.com` 时下到的就是镜像地址。

## 说明

- 同一版本号下可能对应多个构建，靠构建时间区分；页面上的"最新编译时间"就是区分不同构建的依据。
